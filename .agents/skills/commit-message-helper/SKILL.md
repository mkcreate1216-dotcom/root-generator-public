# コミットメッセージ自動提案スキル (commit-message-helper)

## 目的
実装や修正作業が完了した際、ユーザーがそのまま `git commit` に使える、わかりやすく的確な**日本語1行のコミットメッセージ**を考案して提示します。

## 適用ルール
1. **作業完了時の自動提案**:
   - コードの編集、ファイルの新規作成・削除、ビルド設定の調整などの作業がひと段落したターンの末尾で、必ず日本語1行のコミットメッセージを提案します。
2. **フォーマット**:
   - 原則として **Conventional Commits** 形式に準拠します。
   - 構成: `<type>(<scope>): <変更内容の要約（日本語1行）>` または `<type>: <変更内容の要約（日本語1行）>`
   - **文章単体での提示（コマンド形式は禁止）**:
     - `git commit -m "..."` のような git コマンドを含めてはいけません。
     - ユーザーがそのままコミットメッセージ入力欄やツールに貼り付けられるよう、**コミットメッセージの文章単体**のみを提示してください。
   - `type` の分類:
     - `feat`: 新機能の追加
     - `fix`: バグ修正、CI/CD・デプロイエラーの解消
     - `style`: UIデザイン調整、スタイル変更、フォーマット
     - `refactor`: リファクタリング（機能変更なし）
     - `perf`: パフォーマンス改善
     - `chore`: 設定ファイル、ビルドツール、依存関係の更新
     - `docs`: ドキュメントの追加・修正
     - `test`: テストコードの追加・修正
3. **表現のベストプラクティス**:
   - 変更の「結果」だけでなく、「なぜその変更を行ったか」が分かるように記述します。
   - 長くなりすぎず、50〜70文字程度の簡潔な1行にまとめます。
   - 必要に応じてメイン案に加えて短縮版などの別案を1〜2点併記します。

## 出力例
```text
style(ui): ルート検索を主役とする情報設計の再整理とアイコンホバー挙動・未保存配色・メモUIの最適化
```
*(短縮版別案)*:
```text
style(ui): ルート検索ボタンの強調とメモUIのシンプル化、アイコン位置固定および未保存配色の修正
```
