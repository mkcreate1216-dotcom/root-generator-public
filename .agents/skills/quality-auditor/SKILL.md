# 品質・セキュリティ・コンプライアンス監査スキル (quality-auditor)

## 目的
実装や修正作業が完了した際、潜在的なセキュリティ脆弱性、知的財産・ライセンス侵害リスク、UIの表記揺れやトーンの不整合、プロジェクト固有の禁止事項違反を未然に検知・是正し、高品質で安全なプロダクトを維持します。

本スキルは、**作業完了後・コミットメッセージ提案（`commit-message-helper`）の直前**に実行します。

---

## 監査チェックリスト

### 1. セキュリティ & 機密情報 (Security & Secrets)
- [ ] **機密情報の漏洩・ハードコード禁止**:
  - APIキー（Gemini API、Google Maps、Cloudflare API等）、シークレットトークン、秘密鍵、パスワードがコードや設定ファイルに直書きされていないか。
  - 機密情報を含むファイル（`.env`、`.env.local`、認証情報等）が `.gitignore` に含まれているか。
- [ ] **フロントエンド脆弱性 (XSS & HTML Injection)**:
  - Astroの `set:html`、DOMの `innerHTML` / `outerHTML` を使用している場合、外部入力やユーザー提供データが適切にエスケープ・サニタイズされているか。
  - 危険な属性値（`javascript:...` なURL等）がバインドされていないか。
- [ ] **外部リンクの安全性**:
  - `target="_blank"` を付与したすべての `<a>` タグに `rel="noopener noreferrer"` が指定されているか。
- [ ] **クライアントストレージ・通信の安全性**:
  - `localStorage` や `sessionStorage` への入出力時に、適切なデータバリデーションと `try-catch` によるJSONパース例外ハンドリングが行われているか。
  - 外部APIへの通信やURL生成時、オープンリダイレクトや不正なパラメータ注入の余地がないか。
- [ ] **バックエンド・APIルート (Pages API / Worker / D1)**:
  - SQLインジェクションを防ぐため、Cloudflare D1でバインドパラメータ（プリペアドステートメント）を使用しているか。
  - レート制限、リクエストサイズ上限、許可メソッドのチェックが適切か。

### 2. 著作権・知的財産・規約遵守 (Copyright & Compliance)
- [ ] **外部アセットとライセンス**:
  - 新規に追加された画像、音声、フォント、アイコン等の素材は、著作権フリー・商用利用可能なものか。
  - 無断転載、他社サービスのスクレイピング画像、許諾のない商用ロゴ等が混入していないか。
  - 新規追加した npm ライブラリのライセンス（MIT, Apache-2.0 等）に問題がないか（感染性ライセンス等の混入防止）。
- [ ] **サードパーティのブランド・規約遵守**:
  - **Google Maps**: 正式名称表記（「Google マップ」または「Google Maps」）、URLスキームや埋め込み規約を逸脱していないか。
  - **Apple Maps**: 正式名称表記（「Apple Maps」または「マップ」）、連携リンクの形式がガイドラインに沿っているか。
  - **LINE**: 「LINE共有」等の機能で公式ロゴや商標を利用する場合、LINEヤフー社のブランドガイドラインに違反していないか。
  - **X (旧Twitter)**: 最新のブランド表記（Xロゴ、文言）に沿っているか。
- [ ] **免責事項・権利表記の整合性**:
  - 新機能追加に伴い、免責事項（フッターのアコーディオン等）の修正が必要ないか。
  - コピーライト表記（例: `© {displayYear} Fukumimi`）が破損・改変されていないか。

### 3. UI/UX・文言・表記揺れ (UI Consistency & Tone)
- [ ] **プロジェクト用語の統一**:
  - 下記の「たびろーむ 用語集」に基づき、用語がブレずに使用されているか。
  - サービス名: `たびろーむ` または `TabiRome`（誤: `タビローム`, `たびローム`）
  - コア機能名: `スポット`（地点）、`宿泊地`、`出発地点`、`到着地点`、`ルート`（経路）、`旅程` / `プラン`
  - アクションボタン: `追加`、`保存`、`削除`、`共有`、`コピー`、`キャンセル`、`閉じる`
- [ ] **トーン＆マナー (Tone & Manner)**:
  - ユーザー向けメッセージ・案内文・トースト通知は、親しみやすく丁寧な「です・ます」調で統一されているか。
  - エラーメッセージはユーザーを責めず、具体的な次アクションを提示しているか（例: 「スポット名を入力してください」）。
  - 入力欄プレースホルダーの記法統一（例: `例: 浅草寺`、`例: 東京駅` のように `例: ` を先頭に付与）。
- [ ] **文字・記号の統一ルール**:
  - 英数字・記号は原則半角（`Day 1`, `Google Maps`, `2泊3日`）。
  - 句読点（`、` `。`）の使い方が統一されているか。
  - 三点リーダー（`…` vs `...` vs `・・・`）の混在がないか。
- [ ] **アクセシビリティ & レスポンシブ**:
  - アイコン単体のボタンに `aria-label` または `title` が設定されているか。
  - モバイル（375px〜）およびデスクトップ表示で文字の折り返し・はみ出し・コントラスト不足がないか。

### 4. プロジェクト固有ルール・絶対禁止事項 (Project Rules)
- [ ] **LPサンプル表示（「例:」タグ）の非クリッカブル厳守**:
  - LP下部の旅行名サンプル（「京都 2泊3日」「北海道ドライブ」「金沢 週末ひとり旅」等）が、**静的なテキスト・非クリッカブルなピル表示**のままであること。
  - **絶対に `<button>` タグやリンク、`cursor-pointer`、クリックイベント、入力・作成開始処理を追加してはならない**（AGENTS.md 絶対遵守事項）。
- [ ] **その他 AGENTS.md / プロジェクト規約の遵守**:
  - 既存のコメント、docstring、アーキテクチャ設計方針が維持されているか。

## 監査プロセス（実行手順）

1. **変更差分の抽出**:
   - `git diff`、`git status`、新規作成・変更ファイルを走査し、影響範囲を特定する。
2. **4つの監査軸による精査**:
   - 上記チェックリストに基づき、差分コードおよび周辺コードを検証する。
3. **重要度判定 (Severity)**:
   - 🔴 **BLOCKER**: 機密情報漏洩、重大な脆弱性、著作権侵害、AGENTS.md禁止事項違反。直ちに修正が必要（コミット不可）。
   - 🟡 **WARNING**: 表記揺れ、UIトーン不一致、軽微なアクセシビリティ不足。修正を強く推奨。
   - 🟢 **PASS**: 監査項目をすべてクリア。
4. **是正措置**:
   - BLOCKER または WARNING が検出された場合、自律的にコードを修正するか、ユーザーに報告して確認を得る。
5. **コミットメッセージ提案への引き渡し**:
   - 監査をクリアした後、`commit-message-helper` スキルに従い日本語1行のコミットメッセージを提案する。

## 出力フォーマット例

監査実施時は、以下のフォーマットで簡潔に結果を出力します：

```markdown
### 🛡️ 品質・セキュリティ監査結果 (quality-auditor)
- **セキュリティ & 機密情報**: ✅ PASS（ハードコードや脆弱性なし）
- **著作権 & 規約遵守**: ✅ PASS（ライセンス・商標ガイドライン遵守）
- **UI & 表記揺れ**: ⚠️ 修正済み（ボタンの文言「消去」を既存の統一表現「削除」に修正）
- **プロジェクト禁止事項**: ✅ PASS（LPサンプルタグの非クリッカブル維持確認）

**判定**: 🟢 ALL CLEAR
```
